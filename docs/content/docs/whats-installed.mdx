## How the variants are resolved

Platform skills ship as suffixed variants (`pc-userstory-gh`, `pc-userstory-az`,
`pc-userstory-jira`, `pc-userstory-browser`) and the installer copies only the one matching your
backlog platform, renamed to its generic name.

Platform operations for ship, review and backlog are injected directly into the `/ops-*` command
files from `cli/presets/ops-*/` during onboarding, and token-optimization guidance is injected into
`pc-guardrails-generic` marker blocks.

<Callout title="Your own skills survive">
  Step 2 of the wizard removes stale AI files, but never your `.agents/skills/` directory. Any
  `SKILL.md` in a subdirectory there stays put and remains discoverable.
</Callout>

## Markdown linting

`.markdownlint-cli2.jsonc` and `.markdownlint-rules.cjs` land at your project root like `AGENTS.md`
does: copied once if you don't already have them, never overwritten after that. The one rule they
enforce is `no-hard-wrapped-prose` — keep each paragraph on a single physical line instead of
hard-wrapping it at a fixed column. These files are read mostly by agents, and a hard-wrapped `\n`
is ambiguous between a paragraph break and a formatting artifact; one line per paragraph keeps it
unambiguous. Every built-in markdownlint rule is off, including `MD013`, which enforces the
opposite of this convention.

The config ships inert. `pc-repo-verify` already discovers whatever lint script your `package.json`
defines, so wiring it up is three small edits, done once:

```json
{
  "scripts": { "lint:md": "markdownlint-cli2 \"**/*.md\"" },
  "lint-staged": { "*.md": "markdownlint-cli2 --no-globs" },
  "devDependencies": { "markdownlint-cli2": "0.23.2" }
}
```

Add a matching block to your pre-commit hook if you have one; Lyceum's `.husky/pre-commit` is a
working example, guarding on staged `*.md` files so an unrelated commit never pays the cost.

Once `lint:md` exists, `pc-repo-verify` picks it up on its own — no further wiring needed.
